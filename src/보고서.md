# 지능형로봇팀 예비단원 1일차 보고서

## 1. Ubuntu 24.04 설치

### 1-1. 설치 목적

앞으로 지능형로봇팀 활동에서 사용할 개발 환경을 준비하기 위해 Ubuntu 24.04를 설치하였다.

평소에는 Windows를 주로 사용했기 때문에 Linux 환경을 직접 설치하고 사용해 보는 것을 목표로 하였다. 이후 로봇 관련 개발에도 사용할 수 있도록 기본적인 환경을 구성하였다.

### 1-2. 설치 과정

Ubuntu 공식 홈페이지에서 Ubuntu 24.04 64-bit PC(AMD64) Desktop ISO 이미지를 다운로드하였다. 이후 USB를 부팅 디스크로 만들기 위해 Rufus를 사용하였다.

Windows의 디스크 관리에서 기존 파티션의 볼륨을 축소하여 Ubuntu 설치에 사용할 공간(100 GB)을 확보한 후, BIOS에서 USB를 부팅 우선순위로 설정하여 Ubuntu 설치를 진행하였다.

설치 과정에서는 Windows와 Ubuntu를 함께 사용할 수 있도록 Ubuntu를 Windows Boot Manager와 함께 설치하는 방식을 선택하였다. 설치가 완료된 후 재부팅하여 Ubuntu가 정상적으로 실행되는 것을 확인하였다.

---

## 2. Ubuntu 설치 과정에서 발생한 문제와 해결

## 2-1. BitLocker 관련 문제

Ubuntu를 Windows와 함께 설치하는 과정에서 BitLocker와 관련된 문제가 발생하였다.

사용 중인 삼성 노트북의 Windows에서 BitLocker가 활성화되어 있었고, Ubuntu를 설치하기 위해 디스크 파티션을 확인하고 부팅 환경을 변경하는 과정에서 BitLocker가 듀얼부팅에 영향을 줄 수 있다는 것을 확인하였다.

처음에는 파티션만 잘 설정하면 설치가 끝날 것이라고 생각했지만, 인터넷 검색을 해보니 BitLocker가 Windows의 저장장치를 암호화하는 기능이며 운영체제의 부팅 환경이나 파티션을 변경할 경우 복구 키를 요구하거나 Windows 파티션에 정상적으로 접근하지 못하는 문제가 발생할 수 있다는 것을 알게 되었다.

### 2-2. 해결 방법

문제를 해결하기 위해 먼저 Windows에서 BitLocker의 상태를 확인하였다.

`설정` 또는 Windows의 BitLocker 관리 화면에서 암호화 상태를 확인한 후, Ubuntu 설치 과정에서 문제가 발생하지 않도록 BitLocker 보호를 일시 중지하는 방법을 인터넷에서 찾아 적용하였다.

중요한 점은 BitLocker를 무조건 삭제하거나 영구적으로 해제하는 것이 아니라, 듀얼부팅 환경을 구성하는 동안 발생할 수 있는 인증 및 부팅 문제를 방지하기 위해 보호 기능을 일시적으로 중지하는 것이었다.

또한 BitLocker 복구 키가 필요한 상황에 대비하여 복구 키를 확인하고 보관한 후 Ubuntu 설치를 진행하였다.

이후 Ubuntu 설치 및 재부팅 과정에서 Windows와 Ubuntu가 정상적으로 선택되어 실행되는지 확인하였다.

### 2-3. 문제 해결 과정에서 배운 점

이번 문제를 통해 운영체제를 새로 설치할 때 단순히 설치 파일과 디스크 공간만 준비하면 되는 것이 아니라 기존 운영체제의 보안 기능도 확인해야 한다는 것을 알게 되었다.

특히 BitLocker는 평소에는 저장장치를 보호하는 유용한 기능이지만, 듀얼부팅과 같이 부팅 환경이나 디스크 구성이 변경되는 상황에서는 예상하지 못한 문제가 발생할 수 있다는 점을 알게 되었다.

문제가 발생한 뒤 인터넷에서 삼성 노트북과 Ubuntu 듀얼부팅, BitLocker 관련 사례를 검색하면서 비슷한 환경에서 발생한 문제와 해결 방법을 비교하였다. 찾아본 내용 중 현재 상황에 맞는 방법을 적용해서 문제를 해결할 수 있었다.

이 경험을 통해 개발 환경을 구축할 때 문제가 발생하면 무작정 설정을 변경하기보다 **현재 상태를 먼저 확인하고, 정확한 오류나 키워드를 검색하여 해결 방법을 찾는 과정**이 중요하다는 것을 배웠다.

# 3. 개발 편의를 위한 추가 환경 설정

Ubuntu와 ROS2 설치 과정에서 기본적인 프로그램 외에도 실제 개발을 진행할 때 편리하게 사용할 수 있는 환경을 추가로 구성하였다.

교육자료에서도 Ubuntu 환경을 구성하면서 필요한 프로그램이나 설정이 있다면 본인이 인터넷 등을 통해 찾아서 진행하도록 안내하고 있었기 때문에, 인터넷 검색과 AI에게 개발 환경 구성을 추천받아 어떤 도구를 추가하면 좋을지 찾아보았다. 

앞으로 C/C++을 이용한 개발과 로봇 관련 프로젝트를 진행할 것을 고려하여 **Visual Studio Code와 Terminator를 중심으로 개발 환경을 구성하였다.**

## 3-1. Visual Studio Code 설치

### 설치 이유

Ubuntu에서 C/C++ 코드를 작성할 때 기본 텍스트 편집기를 사용하는 것보다 코드 작성에 필요한 기능을 갖춘 개발 환경을 사용하는 것이 편리하다고 판단하였다.

Visual Studio Code는 확장 프로그램을 추가하면 C/C++ 개발이나 Git 관리 등 여러 기능을 사용할 수 있어서 앞으로 프로젝트를 할 때 편할 것 같았다.

따라서 Ubuntu에 Visual Studio Code를 설치하고, 이후 실제 개발에 필요한 확장 프로그램을 추가로 설치하였다.

---

## 3-2. C/C++ 확장 프로그램

C/C++ 개발을 위해 Microsoft에서 제공하는 **C/C++ 확장 프로그램**을 설치하였다.

이 확장 프로그램을 사용하면 C/C++ 코드에서 문법 강조, 코드 자동완성, 오류 확인, 디버깅 등의 기능을 사용할 수 있다.

C언어 프로젝트를 하다 보면 코드가 길어질 수 있기 때문에 자동완성이나 오류 확인 기능이 도움이 될 것 같았다.

또한 단순히 코드를 작성하는 것뿐만 아니라 프로그램을 실행하면서 발생하는 오류를 디버깅할 때도 활용할 수 있기 때문에 C/C++ 개발 환경에서 가장 기본적으로 필요한 확장 프로그램이라고 생각하였다.

---

## 3-3. CMake Tools

C/C++ 프로젝트를 진행하다 보면 소스 파일이 하나의 파일로 끝나지 않고 여러 개의 소스 코드와 헤더 파일로 구성될 수 있다.

이러한 프로젝트에서는 프로젝트를 빌드하기 위한 설정이 필요하기 때문에 **CMake Tools** 확장 프로그램을 추가하였다.

CMake Tools를 이용하면 VSCode에서 CMake 기반 프로젝트를 구성하고 빌드하는 과정을 보다 편리하게 관리할 수 있다.

나중에 프로젝트 파일이 많아질 수도 있기 때문에 미리 설치해 두면 좋을 것 같아서 추가하였다.

---

## 3-4. GitLens

Git 교육을 통해 Git을 이용한 버전 관리 방법을 배웠기 때문에 VSCode 안에서도 Git 변경사항을 쉽게 확인할 수 있도록 **GitLens** 확장 프로그램을 설치하였다.

GitLens를 이용하면 코드가 언제 변경되었는지, 어떤 commit에서 변경되었는지 등을 VSCode 내부에서 확인하는 데 도움을 받을 수 있다.

Git을 터미널 명령어로만 사용하는 것보다 실제 코드와 변경 이력을 함께 확인할 수 있기 때문에 앞으로 Git을 이용해 프로젝트를 관리할 때 유용할 것으로 판단하였다.

다만 Git의 기본적인 동작 원리와 `add`, `commit`, `branch`, `merge` 등의 명령어를 이해하는 것이 우선이라고 생각하였으며, GitLens는 이러한 기능을 대신하기 위한 것이 아니라 Git의 변경 내용을 보다 쉽게 확인하기 위한 보조 도구로 사용하였다.

---

## 3-5. Korean Language Pack

Ubuntu에서 개발 환경을 사용하면서 메뉴와 설정을 보다 편리하게 확인하기 위해 **Korean Language Pack**도 설치하였다.

개발 자체에는 반드시 필요한 확장 프로그램은 아니지만, 처음 Ubuntu와 VSCode 환경을 사용하는 과정에서 각 메뉴와 설정의 의미를 이해하는 데 도움이 될 수 있다고 판단하였다.

또한 코드의 주석이나 문서 등을 작성할 때 한글을 자주 사용하기 때문에 한글 입력 환경도 함께 확인하였다.

---

## 3-6. VSCode 통합 터미널 활용

VSCode에는 별도의 터미널 프로그램을 실행하지 않고도 코드 편집기 내부에서 터미널을 사용할 수 있는 기능이 있다.

이를 활용하면 다음과 같이 하나의 개발 환경에서 작업할 수 있다.

```text

┌─────────────────────────────────────────┐

│              VSCode 코드 작성           │

│                                         │

│       C / C++ 소스 코드 편집            │

│                                         │

├─────────────────────────────────────────┤

│              통합 터미널                │

│ $ gcc main.c -o main                    │

│ $ ./main                                │

└─────────────────────────────────────────┘

```

코드를 수정한 후 바로 아래 터미널에서 빌드하거나 실행 결과를 확인할 수 있기 때문에 창을 여러 개 왔다 갔다 하지 않아도 되어서 편리했다.

---

## 3-7. Terminator 설치

VSCode의 통합 터미널과 별개로 여러 개의 터미널을 동시에 사용해야 하는 상황을 고려하여 **Terminator**도 설치하였다.

Terminator는 하나의 창에서 여러 터미널을 분할하여 사용할 수 있는 프로그램이다.

설치는 다음 명령어를 이용하였다.

```bash

sudo apt update

sudo apt install terminator

```

설치 후 터미널을 여러 영역으로 나누어 사용할 수 있는 것을 확인하였다.

예를 들어 개발 과정에서 다음과 같이 사용할 수 있다.

```text

┌──────────────────┬──────────────────┐

│   프로그램 실행  │   로그 확인      │

├──────────────────┼──────────────────┤

│   파일 작업      │   Git 작업       │

└──────────────────┴──────────────────┘

```

여러 작업을 할 때 터미널 창을 여러 개 따로 열지 않고 한 화면에서 볼 수 있다는 점이 편리했다.

---

## 3-8. 추가 환경 설정을 진행하면서 느낀 점

이번 환경 설정에서는 단순히 팀에서 설치하라고 지정한 프로그램만 설치하지 않고, 앞으로 실제 개발을 진행할 때 어떤 기능이 필요할지 생각해 보았다.

인터넷 검색과 AI를 활용하여 Ubuntu에서 C/C++ 개발을 할 때 사용할 수 있는 프로그램과 VSCode 확장 프로그램을 찾아보았고, 그중 현재 학습 단계에서 실제로 도움이 될 만한 기능을 중심으로 설치하였다.

특히 VSCode의 확장 프로그램은 단순히 많은 프로그램을 설치하는 것보다 **각 확장 프로그램이 어떤 문제를 해결해 주는지 이해하고 필요한 것만 사용하는 것이 중요하다**고 생각하였다.

현재는 C/C++ 코드 작성과 Git 사용에 필요한 기본적인 환경만 구성했고, 앞으로 필요하면 추가로 설치할 예정이다.

# 4. Git 교육 복습 및 실습

## 4-1. Git을 사용하는 이유

Git은 파일이나 코드가 어떻게 바뀌었는지 기록하고 관리할 수 있는 도구이다.

코드를 개발하다 보면 이전에는 정상적으로 작동했던 코드가 수정 이후 오류가 발생할 수 있다. 이때 Git을 사용하면 이전에 저장한 버전으로 돌아가거나 현재 버전과 이전 버전의 차이를 확인할 수 있다.

파일을 여러 개 복사해서 관리하는 것보다 Git으로 기록을 남기는 것이 더 편리하다고 생각했다.

---

## 4-2. Git 저장소 생성

Git을 사용하기 위해 먼저 Git 저장소를 생성할 수 있다.

```bash

git init

```

`git init`을 실행하면 현재 디렉터리를 Git이 관리하는 저장소로 만들 수 있다.

교육에서는 ROS2 workspace의 `src` 내부에 임시 패키지를 만든 후 해당 패키지에서 Git을 초기화하는 방식으로 실습하였다.

예를 들어 패키지는 다음과 같이 생성할 수 있다.

```bash

ros2 pkg create <package_name> --build-type ament_cmake --dependencies rclcpp std_msgs

```

그 후 해당 패키지 디렉터리에서 `git init`을 실행하여 패키지 단위로 Git을 관리하는 과정을 실습하였다.

---

## 4-3. git add와 staging

Git에서 파일을 수정했다고 바로 commit되는 것은 아니다.

먼저 `git add` 명령어를 사용하여 commit할 파일을 선택한다.

```bash

git add test.txt

```

여러 파일을 선택하는 것도 가능하다.

```bash

git add test1.txt test2.txt

```

또한 현재 디렉터리의 변경 내용을 한 번에 staging하려면 다음과 같이 사용할 수 있다.

```bash

git add .

```

여기서 중요한 점은 `git add`가 단순히 파일을 저장하는 명령어가 아니라 **다음 commit에 포함시킬 변경 내용을 staging 영역에 올리는 과정**이라는 것이다.

---

## 4-4. git commit

`git add`를 통해 commit할 파일을 선택한 후 `git commit`을 사용하여 변경 내용을 하나의 기록으로 저장한다.

```bash

git commit -m "첫 번째 커밋"

```

예를 들어 파일을 수정한 뒤 다시 commit할 수 있다.

```bash

git add .

git commit -m "두 번째 수정"

```

이렇게 하면 각각의 수정 내용이 별도의 commit으로 기록된다.

Git에서 `add`와 `commit`을 나누어 놓은 이유는 여러 파일의 변경사항 중 실제로 기록하고 싶은 것만 선택하여 하나의 commit으로 만들 수 있기 때문이다.

---

## 4-5. git status

현재 Git 저장소의 상태를 확인할 때는 다음 명령어를 사용한다.

```bash

git status

```

`git status`를 사용하면 아직 commit되지 않은 파일이나 staging된 파일 등을 확인할 수 있다.

따라서 작업을 진행하면서 현재 어떤 파일이 수정되었는지, 어떤 파일이 commit 대상인지 확인하기 위해 자주 사용할 수 있는 명령어라고 이해하였다.

---

## 4-6. git log

지금까지 생성된 commit 기록을 확인할 때는 `git log`를 사용할 수 있다.

```bash

git log --all --oneline

```

`--oneline` 옵션을 사용하면 commit 기록을 한 줄 단위로 간단하게 확인할 수 있다.

이를 이용하면 여러 번 commit을 진행한 후 과거에 어떤 작업을 기록했는지 확인할 수 있다.

---

## 4-7. git diff

Git에서 현재 파일과 이전 commit의 차이를 확인하기 위해 `git diff`를 사용할 수 있다.

```bash

git diff

```

이 명령어를 이용하면 commit하기 전에 내가 어떤 부분을 수정했는지 확인할 수 있다.

교육에서 배운 것처럼 commit하기 전에 변경사항을 확인하면 불필요한 수정이나 의도하지 않은 변경을 commit하는 것을 줄일 수 있다.

또한 `git difftool`을 이용하면 변경 내용을 보다 시각적으로 비교할 수 있다.

```bash

git difftool

```

특정 commit과 비교할 경우 commit ID를 활용할 수 있다.

```bash

git difftool <commit_id>

```

Git을 단순히 버전 저장 도구로 사용하는 것이 아니라 **commit하기 전에 변경사항을 확인하는 과정까지 포함하여 사용하는 것이 좋은 습관**이라는 점을 배웠다.

---

# 5. Git Branch 복습 및 실습

## 5-1. Branch의 필요성

프로젝트를 진행하다 보면 현재 정상적으로 작동하는 코드를 직접 수정하여 새로운 기능을 테스트해야 하는 경우가 있다.

이때 기존 코드를 바로 수정하면 문제가 발생했을 때 원래 상태로 돌아가기 번거로울 수 있다.

Git의 branch를 사용하면 현재 코드를 기반으로 별도의 작업 공간을 만들어 새로운 기능을 테스트할 수 있다.

직접 사용해 보니 branch는 기존 코드를 유지하면서 다른 작업을 해볼 수 있는 공간처럼 느껴졌다.

---

## 5-2. Branch 생성

새로운 branch는 다음과 같이 생성할 수 있다.

```bash

git branch test_27

```

생성한 branch로 이동하려면 다음 명령어를 사용한다.

```bash

git switch test_27

```

현재 branch가 무엇인지 확인하려면 다음과 같이 확인할 수 있다.

```bash

git status

```

또는 branch 목록을 확인할 수도 있다.

```bash

git branch

```

---

## 5-3. Branch에서 파일 수정

`test_27` branch로 이동한 후 새로운 파일을 생성하고 commit하면 해당 변경 내용은 `test_27` branch에 기록된다.

```bash

git add .

git commit -m "테스트 파일 추가"

```

이후 main branch로 이동하면 branch에서 추가했던 변경사항이 main에 바로 적용되지 않는 것을 확인할 수 있다.

```bash

git switch main

```

main으로 다시 이동했을 때 변경 내용이 바로 적용되지 않는 것을 보고 branch가 따로 관리된다는 것을 확인할 수 있었다.

---

## 5-4. Branch의 commit 기록 확인

여러 branch의 commit 기록을 한 번에 확인하기 위해 다음 명령어를 사용할 수 있다.

```bash

git log --oneline --all --graph

```

`--graph` 옵션을 이용하면 branch가 어떻게 분리되고 다시 합쳐지는지 시각적으로 확인할 수 있다.

따라서 branch를 많이 사용하는 프로젝트에서는 단순한 commit 목록보다 branch 구조를 이해하는 데 도움이 된다.

---

# 6. Git Merge

branch에서 작업한 내용을 main branch에 반영하기 위해 `merge`를 사용할 수 있다.

먼저 main branch로 이동한다.

```bash

git switch main

```

그 후 작업한 branch를 merge한다.

```bash

git merge test_27

```

그러면 `test_27`에서 작업한 내용이 main branch에 합쳐진다.

### Merge Conflict

두 branch에서 동일한 부분의 코드를 서로 다르게 수정한 경우 충돌(Conflict)이 발생할 수 있다.

이 경우 Git이 어떤 코드를 선택해야 하는지 자동으로 결정하지 못하기 때문에 충돌이 발생한 부분을 직접 확인하고 원하는 코드로 수정해야 한다.

수정을 완료한 후 다시 staging하고 commit하여 충돌 해결을 완료할 수 있다.

```bash

git add .

git commit -m "merge conflict 해결"

```

이번 실습을 통해 branch는 단순히 코드를 복사하는 기능이 아니라 **안전하게 새로운 작업을 진행하고 검증한 뒤 기존 코드에 반영하기 위한 도구**라는 점을 이해하였다.

---

# 7. Git 실습을 통해 이해한 작업 흐름

이번 교육에서 배운 내용을 종합하면 기본적인 Git 작업 과정은 다음과 같이 정리할 수 있다.

```text

파일 작성 및 수정

   ↓

git status

   ↓

변경사항 확인

   ↓

git diff

   ↓

commit할 파일 선택

   ↓

git add

   ↓

git status

   ↓

git commit

   ↓

git log로 기록 확인

```

새로운 기능을 개발하는 경우에는 branch를 활용할 수 있다.

```text

         main

          │

          ├───────────────┐

          │               │

          │          test\_27 branch

          │               │

          │          기능 수정/테스트

          │               │

          │             commit

          │               │

          └────── merge ──┘

                  ↓

                 main

```

이런 방식으로 기존 코드를 유지하면서 새로운 기능을 테스트하고 문제가 없으면 main에 합칠 수 있다.

# 8. 이번 교육을 통해 배운 점

이번 교육에서는 Ubuntu 설치부터 개발 환경 설정, Git 기본 사용법까지 직접 해볼 수 있었다.

Ubuntu 설치 과정에서는 운영체제를 설치하는 것뿐만 아니라 디스크 파티션과 BIOS, 부팅 설정 등 여러 요소를 함께 고려해야 한다는 것을 알게 되었다. 설치 중 문제가 생겼을 때 인터넷으로 검색하면서 해결해 보았는데, 오류 내용을 정확하게 확인하는 것이 중요하다는 것을 느꼈다.

또한 VSCode, Terminator, 한글 입력 환경 등을 직접 구성하면서 개발 환경도 그냥 프로그램을 설치하는 것에서 끝나는 것이 아니라 앞으로 할 작업에 맞게 필요한 것을 추가해야 한다는 것을 알게 되었다.

Git에서는 `add`, `commit`, `status`, `log`, `diff` 등의 기본 명령어뿐만 아니라 branch와 merge의 개념까지 복습하였다. 특히 `git add`를 통해 commit할 내용을 선택하고 `git commit`으로 하나의 작업 기록을 남긴다는 구조를 이해하는 것이 중요하다고 생각하였다.

또한 branch를 이용하면 기존 코드에 직접 변경을 가하지 않고 새로운 기능을 테스트할 수 있기 때문에 앞으로 팀 프로젝트에서 코드를 수정할 때 매우 유용하게 사용할 수 있을 것이라고 생각하였다.

이번 교육에서 배운 Git 사용 방법을 단순히 명령어를 외우는 것에 그치지 않고, 앞으로 실제 프로젝트를 진행하면서 **변경사항 확인 → staging → commit → branch를 통한 기능 개발 → merge**의 흐름으로 활용하는 것을 목표로 하겠다.
